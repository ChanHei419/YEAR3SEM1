Q7. Draw the class diagram of the code shown in Q2.

程式碼片段：

class MyClass<T> {
    public static T GenItem(){
        return new T();
    }
}

👨‍🏫 教學解說

這題考的是泛型類別 (Generic Class) 的畫法。

  • 概念： 根據 lec3_uml (2).pdf 第 18 頁 (Template Class)，泛型參數（如 T）應該畫在類別名稱右上角的虛線方框中。
  • 方法：
    1. 畫一個類別框，名稱為 MyClass。
    2. 在右上角標註泛型參數 T。
    3. 加入方法 GenItem。因為它是 public，前面加 +。
    4. 因為它是 static 方法，根據 UML 標準通常加底線（或如 PPT 第 6 頁所示用 $）。
    5. 回傳型別是 T。
📚 參考來源: lec3_uml (2).pdf, Slide 18
classDiagram class MyClass~T~ { +GenItem() T$ }

Q8. Draw the class diagram of the code shown in Q6.

程式碼片段：

public class A { public virtual void foo() ... }
public class B : A { public override void foo() ... }

👨‍🏫 教學解說

這題考的是繼承 (Inheritance / Generalization) 的畫法。

  • 概念： 根據 lec3_uml (2).pdf 第 13 頁 (Inheritance)，繼承關係使用實線 + 空心三角形箭頭，箭頭指向父類別 (Base Class)。
  • 方法：
    1. 畫出類別 A (父類別) 和類別 B (子類別)。
    2. 兩者都有 foo() 方法，且都是 public (+)。
    3. 畫一條線從 B 指向 A，箭頭端是空心三角形。
📚 參考來源: lec3_uml (2).pdf, Slide 13
classDiagram class A { +foo() } class B { +foo() } A <|-- B

Q9. Draw the class diagram for the following C# code.

程式碼片段：

public abstract class Base {
    private int i;
    protected abstract void bar();
}
public class Derived : Base {
    public int i;
    protected override void bar() { }
}

👨‍🏫 教學解說

這題考的是抽象類別與可見性修飾符 (Visibility)。

  • 概念：
    • 抽象類別/方法： 根據 PPT 第 14 頁，抽象名稱通常用斜體表示。在 Mermaid 中，我們使用 * 來標記抽象方法，使其呈現斜體。
    • 可見性 (Slide 6)：
      • private 用 -
      • protected 用 #
      • public 用 +
  • 分析：
    • Base 是抽象類別。i 是 private (-i)。bar() 是 protected abstract (#bar())。
    • Derived 繼承 Base。它有一個自己的 public i (+i)，並實作了 bar()。
📚 參考來源: lec3_uml (2).pdf, Slide 6, 13, 14
classDiagram class Base { <> -int i #bar()* } class Derived { +int i #bar() } Base <|-- Derived

(註：bar() 為斜體，代表抽象方法)

Q10. Draw the sequence diagram for the following C# code.

👨‍🏫 教學解說

這題考的是循序圖 (Sequence Diagram)，展示物件之間的互動順序。

  • 概念： 參考 PPT 第 36-40 頁。
    • Lifeline (生命線)： 代表參與的物件 (如 :First, :Second)。
    • Activation (活動條)： 長條矩形，代表該物件正在執行程式。
    • Message (訊息)： 實線箭頭代表呼叫方法，虛線箭頭代表返回。
    • Creation： 指向物件本身的箭頭代表 new。

    1. Main 建立 First 物件 (f)。
    2. Main 呼叫 f.callSe()。
    3. 進入 callSe： f 建立一個 Second 物件 (s)。
    4. f 呼叫 s.yay()。
    5. (印出 "and")
    6. f 再次呼叫 s.yay()。
    7. 回到 Main： Main 建立一個新的 Second 物件 (s)。
    8. Main 呼叫這個新 s 的 yay()。
    9. Main 再次呼叫 f.callSe() (重複步驟 3-6)。

Q14. Draw the cause-effect graph (with the mask constraint).

情境： "Right-click" -> Simplified menu. "Hold Ctrl + Right-click" -> Full menu.

👨‍🏫 教學解說

這題考的是因果圖 (Cause-Effect Graph)，特別是遮罩約束 (Mask Constraint)。

  • 概念： 參考 lec9_testing (1).pdf 第 21-22 頁。
    • Cause (原因/輸入)： C1 = Right Click (右鍵), C2 = Hold Ctrl (按住 Ctrl)。
    • Effect (結果/輸出)： E1 = Simplified Menu (簡易選單), E2 = Full Menu (完整選單)。
    • 邏輯：
      • 如果只有 C1 -> E1。
      • 如果 C1 和 C2 同時發生 -> E2。
    • Mask Constraint (遮罩約束)： PPT 第 22 頁提到了 m (Mask) 約束。
      在這裡的意思是：當按下 Ctrl (C2) 時，原本右鍵會觸發的簡易選單 (E1) 會被「遮蔽」或「抑制」，轉而觸發完整選單。
  • 畫法：
    1. 畫出 C1, C2, E1, E2。
    2. C1 指向 E1 (基本行為)。
    3. C1 和 C2 共同指向 E2 (組合行為)。
    4. 關鍵點： 畫一條帶有 Mask (M) 標記的約束線，從 C2 指向 E1。這表示「C2 的存在會遮蔽 E1 的發生」。
📚 參考來源: lec9_testing (1).pdf, Slide 21, 22

紅色虛線 代表 Mask Constraint：
當 C2 (Ctrl) 為真時，E1 (Simplified Menu) 被強制設為 False (被遮蔽)。
